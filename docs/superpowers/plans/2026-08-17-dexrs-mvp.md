# dexrs MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a source-installable Rust CLI that can run as `dexrs` or `dex`, preserves dex-compatible JSONL task storage, and prevents concurrent writer corruption.

**Architecture:** The CLI will be a small Rust binary crate with shared command code in `src/lib.rs` and two thin binaries in `src/bin/dexrs.rs` and `src/bin/dex.rs`. Storage concerns live behind a repository module that resolves store directories, takes cross-process locks for mutations, validates relationships, and writes JSONL atomically.

**Tech Stack:** Rust edition 2024, `clap`, `serde`, `serde_json`, `anyhow`, `thiserror`, `time`, `fs4`, `tempfile`, `assert_cmd`, `predicates`.

**Spec:** `docs/superpowers/specs/2026-08-17-dexrs-design.md`

## Global Constraints

- Preserve `.dex/tasks.jsonl` compatibility with the current dex task shape.
- Resolve stores like dex: `DEX_STORAGE_PATH`, then `<git-root>/.dex`, then `~/.config/dex/local`.
- Wrap every mutating command in an exclusive cross-process locked transaction.
- Write JSONL via temp file, fsync, atomic rename, and directory sync where supported.
- Install a canonical `dexrs` binary and a compatibility `dex` binary that runs the same CLI code.
- Do not modify, uninstall, or move the user's existing npm/pnpm dex installation unless explicitly asked.
- Initial commands: `init`, `dir`, `status`, `create` / `add`, `list` / `ls`, `show`, `start`, `complete` / `done`, `edit` / `update`, `delete` / `rm` / `remove`.
- Deferred commands: MCP, GitHub sync, Shortcut sync, archive/import/export, shell completions, `plan`, and full config management.

---

## File Structure

- `Cargo.toml`: crate metadata, dependencies, and both binary targets.
- `src/lib.rs`: public `run(args, stdout, stderr)` entrypoint used by both binaries.
- `src/bin/dexrs.rs`: calls `dexrs::main_entry()`.
- `src/bin/dex.rs`: compatibility binary that calls the same entrypoint.
- `src/cli.rs`: `clap` command and argument definitions.
- `src/task.rs`: dex-compatible task struct, status helpers, ID generation, JSONL serialization.
- `src/store.rs`: store discovery, file paths, loading, locked transactions, atomic writes.
- `src/validate.rs`: parent/child and blocker relationship validation.
- `src/commands.rs`: command implementations and output formatting.
- `tests/common/mod.rs`: test helpers for isolated temp stores and command execution.
- `tests/store_discovery.rs`: store resolution tests.
- `tests/jsonl_compat.rs`: dex JSONL fixture parsing and round-trip tests.
- `tests/cli_commands.rs`: CLI behavior tests for all MVP commands.
- `tests/concurrency.rs`: many-process writer regression test.
- `tests/fixtures/dex-tasks.jsonl`: representative dex-compatible task records.
